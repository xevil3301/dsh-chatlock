# DSH Chatlock

给 DeepSeek Harness 加两样东西。一个把会话锁起来，一个把目录锁起来。

## 事情是这样的

有人在群里问了一句，说他 DSH 里有些会话不想被任何人看见，能不能加个密码。

我说这有什么难的。

然后真动手了才发现，难的从来不是密码。难的是「你凭什么觉得它真的藏住了」。我在这个项目上改了七轮，每一轮都是被一个「我以为没问题」的地方打回来的。所以这篇 README 我不想写成功能清单，我想把它当成一份验尸报告来写，顺便告诉你这东西到底能挡住谁。

## 它到底干了两件事

第一件事是聊天锁。你在设置里设一个密码，然后在侧栏把某个会话锁上。下次打开它，会话区会被一层遮罩盖住，同时整个正文模糊掉，弹一个密码框。密码错了就是错了，一小时的暴力尝试也换不来一个字。

密码只存 scrypt 派生值，明文不落盘。「已经解锁」这个状态只活在内存里，进程一重启就全没了，这也是最可靠的一把自动锁。

第二件事是保险箱。你登记一个目录，点一下加密，整个目录里每个文件都会被换成 AES-256-GCM 的密文，明文删掉。锁定之后你在资源管理器里打开它，看到的是 `.dsh-chatlock/enc/` 下面一堆哈希命名的 `.bin`，连原文件名都看不出来。

这一条我专门验过。不是肉眼看的，是把密文按字节读出来搜原始路径、原始文件名、甚至 JSON 字段名，一个都搜不到。

## 装

这个插件不上架也能用，它就是个普通的 DSH 插件包，两个半边的入口都在仓库里。

```bash
git clone https://github.com/xevil3301/dsh-chatlock
cd dsh-chatlock
node install.mjs                 # 默认装进 desktop profile
node install.mjs --profile web   # 或者别的 profile
```

装完**必须重启 dsh**。宿主那半边不热重载，我试过改文件等十二秒，日志里一行新东西都没有。

然后设置 →「聊天锁」→ 设密码。侧栏把鼠标移到任意会话上，会冒出一个小锁，点它。

## 它能挡住谁，挡不住谁

这一段是全文最该读的部分。

「别人打开本地文件夹必须经过 DSH」这句话，在应用层是不成立的。Windows 不会问一个进程「你经过 DSH 了吗」，Explorer、cmd、任何一个程序读文件，走的都是文件系统。想真正做到「打开目录先弹密码」，只有一条路，就是挂一个文件系统驱动，WinFsp 或者 Dokan，真实数据永远是密文，解锁之后由驱动透明解密，Explorer 里才看得见一个正常文件夹。

那是另一个量级的工程。这一版给你的，是下面这三层里的第二层。

| 层 | 做到什么 | 挡得住谁 | 代价 |
| --- | --- | --- | --- |
| 一 · 界面锁 | 不输密码看不见会话内容 | 走到你电脑前、能操作 DSH 的人 | DOM 里仍有文字，磁盘上的会话日志也没动 |
| 二 · 磁盘锁 | 目录里只有密文，文件名也加密 | 直接打开或拷走目录的人，拿走硬盘的人 | 解锁期间磁盘上是明文 |
| 三 · 虚拟盘 | 数据永远密文，驱动透明解密 | 除了解锁中的这台机器以外全部 | 要装驱动加自建 FS 后端，没做 |

还有一条正交的线，对方用的是哪个 Windows 账户。

要是另一个人用**另一个 Windows 账户**登录这台机器，那 NTFS ACL 就够了，`icacls` 一条命令的事，甚至不需要密码。加密真正派上用场，是在你把文件拷走、换机器、或者硬盘被人拿走的时候。

要是对方用**同一个 Windows 账户**，ACL 一点用都没有。这种情况下只有第三层才真正成立，第二层能做的是把明文的时间窗口压到最短。

所以我加了三个开关，专门压这个窗口。保险箱解锁之后密钥只留在内存，空闲十五分钟（可调）就自己锁回去，不用你再输一遍密码。你也可以点「立即锁全部保险箱」，同样不用密码。进程退出等于所有密钥蒸发。

但进程被强杀是没有清理钩子的。所以别把正在写入的工作区当保险箱用，它是归档区，不是工作区。

## 我踩的三个坑

第一个，白底白字。

密码框的主按钮一开始是空白的，只有一个白框，什么字都没有。查下来是配色的问题，我用了 `--dsw-alias-brand-primary` 当背景，又自己写死了 `color: #fff`。而这个变量在暗色主题里是 `#f9fafb`，近白。白底白字，按钮没有消失，它只是看不见。

正确的写法是用主题里本来就成对的那一组，`--dsw-alias-button-primary-fill` 配 `--dsw-alias-label-primary-foreground`。暗色主题下就是近白按钮配近黑字，跟官方主按钮一模一样。

第二个，`--dsw-alias-bg-layer-4` 根本不存在。

我拿它当输入框底色用了很久，样式没崩，因为 `var()` 有 fallback，不报错，静默吃默认值。直到我把主题里四百多个变量全拉出来对了一遍，才发现这个 token 一次都没定义过。现在整份 CSS 用的十四个变量，每一个都能在主题里找到定义，两套主题的值我都核过。

第三个，也是最要命的一个，manifest 明文存了文件名。

保险箱加密了所有文件，但它的清单 `manifest.json` 里写着原始相对路径。也就是说别人打开目录，虽然内容读不出来，但能一眼看到「客户资料/2026Q3/报价单.md」这个文件名。加密了，等于没加密。

现在清单也加密了，用同一把钥匙，同一套容器格式。顺手还修了一个更隐蔽的问题，如果拿错误的口令去锁一个已经锁着的保险箱，旧代码会把清单当成「没锁过」重新扫一遍，然后用错的钥匙覆盖掉真正的文件清单。那个目录就永久救不回来了。现在这种情况直接拒绝，不动一个字节。

## 自检

四个套件，跑完你会知道它到底行不行。

```bash
node scripts/audit.mjs       # 死代码审计，僵尸导出与多余 import
node test/smoke.mjs          # 口令哈希、授权过期、保险箱加解密往返
node test/host-fake.mjs      # 假 ctx 跑 host 半边，路由 / ctx.fs 守卫 / 保险箱全流程
node test/client-wire.mjs    # 假 window 跑 client 半边，自注册与四个槽位
```

还有一个真机验证，它会按 DSH 自己的算法签一个浏览器会话 cookie，等价于一个已登录的标签页，然后打运行中的实例。

```bash
node test/live-check.mjs --port <你的端口>
node test/live-check.mjs --mutate     # 写入往返，跑完自己清干净
```

为什么需要签名 cookie。因为 DSH 的 `/api` 栅栏不是「回环就放行」，回环只是第一道，真正放行的是浏览器会话签名 cookie。命令行拿不到它，curl 一律 401，你会误判成插件没装上。

## 边界，说在前面

聊天锁是界面锁，不是磁盘加密。DSH 启动要读会话日志才能出会话列表，把这些文件加密了它自己就起不来。要磁盘级的保护，把导出的会话或者你的私密资料目录登记成保险箱。

保险箱是整目录上锁和解锁，不是实时透明加密。要做到边用边透明，需要的还是上面说的那个文件系统驱动。

符号链接不跟随。单文件超过 512MB 会跳过并在结果里点名，不会静默漏掉。保险箱路径不允许互相嵌套，内外两把盐各管一半，加密状态会打架。

保险箱忘记密码，数据不可恢复。scrypt 派生，没有后门，没有找回。这是设计，不是缺陷。

## 最后

这玩意儿一开始只是「加个密码」，最后变成了一次把「我以为什么是安全的」全部推翻重来的过程。三层现实的表格、三个坑、四套自检，都是被真问题打出来的，不是设计出来的。

我自己的判断是，它能挡住大部分日常场景，比如室友、同事、来你家玩的朋友，以及那些不小心走错屋子的目光。挡不住的是有心人拿走了硬盘，或者你解锁的机器就摆在别人桌上。

想清楚这一点再用它，比多加密一层更有用。
